# Gate① 日経VI条件の妥当性検証

作成日: 2026-09-11
対象: `config/config.yaml` の `gate_vi` セクション

```yaml
gate_vi:
  vi_threshold: 20          # VI <= 20
  vi_10d_avg_threshold: 20  # VI 10日平均 <= 20
  vi_10d_std_threshold: 1.5 # VI 10日標準偏差 <= 1.5
  vi_10d_slope_threshold: 0.1 # VI 10日回帰の傾き <= 0.1
```

## 0. 結論（先に要約）

**「厳しすぎる」という直感は妥当。ただし本質的な問題は閾値 20 という水準ではなく、
「絶対値で固定している」という設計そのものにある。**

1. 日経VIの直近52週レンジは **18.77〜66.65**。`VI<=20` を満たす日は1年でほぼ皆無であり、
   さらに `10日平均<=20`（＝10日間ずっと20以下）まで要求するため、
   **直近1年間、Gate① は構造的に成立し得なかった**。
2. リポジトリの実記録（17営業日）でも Gate① 成立は **0日**。
3. シミュレーション（137年相当）では、高VIレジームの年の **53% が年間発火ゼロ**。
   一方、低VIレジームの年は年7回発火する。つまり「静穏な年しか稼働しない」設計になっている。
4. 4つのサブ条件は互いに強く相関しており、**独立した情報をほとんど持っていない**。
   特に `SD10<=1.5` は「VI水準が低い」ことの言い換えでしかない。
5. 損益面では、4通りの設定（delta/premium × 保有5日/10日）すべてで現行条件が下位に沈んだ。
   ただしプット買いの損益はファットテールが極端で、**この差は統計的に有意ではない**。
   言えるのは「**厳しさが損益を改善しているという証拠は無い**」という否定的結論まで。
6. 改善方向は「閾値を20→25に緩める」ではなく、
   **相対水準（VIの1年パーセンタイル）＋変動係数CV（SD/平均）への置き換え**。

## 1. 検証方法

### 1.1 データの制約（重要）

本セッションの実行環境はネットワークegressポリシーにより
`indexes.nikkei.co.jp` / `jpx.co.jp` / Yahoo Finance / stooq いずれにも到達できず、
**実際の日経平均・日経VIの時系列を取得できなかった**。
そのため以下の3種類の材料を組み合わせて検証した。

| 材料 | 内容 | 位置づけ |
|---|---|---|
| ① 実記録 | `history/signals.jsonl` の17営業日（2026-08-19〜09-10）の実VI・実判定 | 実データ。ただしN=17 |
| ② 公表統計 | 日経VIの直近52週レンジ 18.77〜66.65、常態レンジ20〜30pt、2026-09-02時点25.55 等 | 実データ。水準感の裏取り |
| ③ シミュレーション | ②に合わせてキャリブレーションしたモンテカルロ 137年相当 | 統計的検出力の確保 |

**③の数値は絶対値としてではなく、バリアント間の相対比較として読むこと。**

### 1.2 シミュレータのキャリブレーション

`scripts/backtest_gate_vi/vi_sim.py`

- VI: 対数OU過程（平均回帰半減期20営業日）＋レバレッジ効果＋レジーム遷移（長期平均 16/19/23/28 を遷移）
- 株価: VIを期待ボラとし、分散リスクプレミアム0.78・t分布(自由度4)・多日急落カスケード
- 急落カスケード: -10%級を年0.65回、-5%級を年2.5回（日経の実績頻度に合わせた）

達成した統計量（実績との対応）:

| 指標 | シミュレーション | 実データの目安 |
|---|---|---|
| VI中央値 | 20.8 | 20〜22 |
| VI日次対数変化の標準偏差 | 0.056 | 0.05〜0.07 |
| 株価リターンとVI変化の相関 | -0.66 | -0.6前後 |
| 年率ボラティリティ | 19.7% | 18〜22% |
| 年率リターン | +8.9% | +9%程度（2010〜） |
| 今後20日に-10%超の下落が起きる日の割合 | 7.9% | — |

### 1.3 オプション評価

- Black-Scholes（金利0）＋プットスキュー（対数マネネス-10%でATM比+5.5vol）
- 満期は各月第2金曜、営業日DTE 18〜28（config準拠）
- スプレッド: 片道 `max(1円, プレミアムの1.2%)`（日経225オプションの呼値・板の実勢）
- イグジット: config の `stop_loss.time_based_days`（5営業日）、2倍到達で半分利確
- 建玉選択は2モードで実施（下記 4.2 の理由による）
  - **delta モード**: 目標デルタ -0.30（`delta_range` 準拠）
  - **premium モード**: プレミアム20〜40円（`premium_range` 準拠）

| 条件 | 充足 |

### 2.2 サブ条件の相関構造（シミュレーション137年）

| 条件 | 単独通過率 | 条件付き通過率 |
|---|---|---|
| ① `VI <= 20` | 49.1% | — |
| ② `VI_MA10 <= 20` | 48.7% | — |
| ③ `VI_SD10 <= 1.5` | 63.6% | ①②成立下で **89.6%** |
| ④ `傾き <= 0.1` | 62.6% | ①②③成立下で 71.8% |
| **4条件すべて** | **28.2%** | — |

条件を1つずつ外したときの通過率:

| 外す条件 | 通過率 | 現行比 |
|---|---|---|
| ① VI水準 | 29.0% | 1.0倍 |
| ② MA10 | 30.5% | 1.1倍 |
| ③ SD10 | 31.4% | 1.1倍 |
| ④ 傾き | 39.3% | 1.4倍 |

**どの条件を外しても通過率がほとんど変わらない = 4条件は独立した情報を持っていない。**
とくに③は、VI水準が低ければ自動的に満たされる。VI帯別のSD10中央値は以下の通りで、
**SD10はVI水準にほぼ比例する**ためである。

| VI帯 | SD10中央値 | CV中央値 | `SD10<=1.5` 通過率 |
|---|---|---|---|
| 13〜17 | 0.79 | 0.051 | 90% |
| 17〜20 | 1.06 | 0.057 | 79% |
| 20〜24 | 1.30 | 0.060 | 63% |
| 24〜30 | 1.77 | 0.068 | 36% |
| 30以上 | 2.76 | 0.080 | 10% |

つまり `SD10 <= 1.5` は「安定性」の条件ではなく **実質3本目のVI水準条件**として働いている。
安定性を見たいなら CV（= SD10 / MA10）を使うべきで、CVならVI水準にほぼ依存しない
（0.051〜0.080）。実記録17日のCV中央値0.079もこの範囲に収まる。

#### 補足: シミュレータはむしろ現行条件に甘い

実記録17日（VI 21.9〜32.4）の SD10 中央値は **2.28**、CV中央値 0.079 だったのに対し、
シミュレーションの同じVI帯（24〜30）は SD10 中央値 1.77、CV中央値 0.068 で、
**シミュレータのほうが VI が滑らかに動いている**（サンプルが17日と短く荒れた局面なので
過度に合わせ込むべきではないが、方向としてはそうなる）。

VIのボラティリティ（σv）を実データ寄りに上げたときの現行Gate①通過率:

| 設定 | VI日次対数変化σ | VI24-30帯のSD10中央値 | 現行Gate①通過率 |
|---|---|---|---|
| 本検証の基本設定 | 0.057 | 1.74 | 24.4% |
| 実データ寄り | 0.066 | 2.02 | 20.6% |
| さらに荒い | 0.078 | 2.33 | **16.7%** |

**本レポートの頻度分析は、現行条件の厳しさを最大1.5倍ほど過小評価している可能性がある。**
CVベースの条件はこの感応度が小さく、その意味でも頑健。

暦年ごとのVI平均でレジームを層別した、年間エントリー発火回数:

## 3. 予測力の検証：低VIは急落の前触れか

Gate②A・B・Trigger③ が成立した日を、エントリー時のVI水準で層別し、
その後20営業日の下落を集計した（シミュレーション137年）。

| エントリー時VI | N | 今後20日の平均最大下落 | -5%超が起きた割合 | -8%超が起きた割合 |
|---|---|---|---|---|
| 〜16 | 320 | -2.18% | 11.6% | 5.3% |
| 16〜18 | 341 | -2.19% | 13.8% | 6.5% |
| 18〜20 | 359 | -2.90% | 20.3% | 10.3% |
| 20〜22 | 310 | -3.11% | 22.9% | 11.9% |
| 22〜25 | 299 | -3.38% | 25.1% | 12.0% |
| 25〜30 | 262 | -3.90% | 30.9% | 14.9% |
| 30〜 | 106 | -5.47% | 45.3% | 23.6% |

**単調に効いている。しかも Gate① が望む方向とは逆である。**
VIが低いほど、その後の急落確率は低い（ボラティリティ・クラスタリング）。

Gate① 成立日（現行条件）の -5%超ドローダウン発生率は **14.6%** で、
全営業日平均の 24.2% より **低い**。

> つまり Gate① は「暴落を当てにいくフィルタ」としては逆効果である。
> Gate① の存在意義は **予測ではなく、オプションが安く買えること（コスト面）に限られる**。

したがって「低VIで安く買える利益」と「低VIでは急落が起きにくい損失」の
どちらが勝つかを、実際の損益で判定する必要がある。

### 4.1.1 ただし損益差は統計的に有意ではない（重要）

1トレードあたり平均損益%のブートストラップ95%信頼区間（4000回）:

| バリアント | delta/5日 平均 | 95%CI | premium/10日 平均 | 95%CI |
|---|---|---|---|---|
| ゲート無し | -9.0% | [-15.2, -2.6] | -10.9% | [-39.4, +25.6] |
| 現行 V1 | -10.5% | [-20.0, -0.4] | -21.6% | [-69.0, +63.6] |
| 相対<=30% | -10.9% | [-20.6, -0.0] | +8.9% | [-53.9, +103.6] |
| 相対<=40% + CV<=0.08 | -7.7% | [-18.4, +4.9] | +3.3% | [-57.2, +106.3] |

プット買いの損益は極端なファットテール（全損が約半数、10倍超が1〜2%）であり、
137年相当・数百トレードでも信頼区間は非常に広い。
V0との差が有意になったのは delta モードの「水準25+SD<=2.5」と
「(水準<=25 or 相対<=40%)+CV<=0.10」だけである。

> したがって損益データから言えるのは
> **「現行の厳しさが損益を改善しているという証拠は無い」**という否定的結論までであり、
> 「現行が明確に劣る」とまでは言えない。
> 一方、**発火頻度・レジーム依存性・条件の冗長性（2章）は統計的にも構造的にも明確**で、
> ここが判断の主材料になる。

### 4.2 付随して判明した設定の不整合

バックテストを組む過程で、Gate①とは別に2点の不整合が見つかった。
**Gate①の話とは独立した問題なので、別途の判断が必要。**

#### (a) `premium_range` と `delta_range` は同時に満たせない

日経平均65,000円・VI=20・残存25暦日でのプット理論価格:

| 権利行使 | OTM率 | 理論価格 | デルタ |
|---|---|---|---|
| 55,000 | -15.4% | 23円 | -0.013 |
| 56,000 | -13.8% | 36円 | -0.020 |
| 62,000 | -4.6% | 452円 | -0.204 |
| 63,000 | -3.1% | 665円 | -0.282 |
| 64,000 | -1.5% | 960円 | -0.378 |

`premium_range: 20〜40円` が指すのは **デルタ -0.01〜-0.02 の超深いOTM**であり、
`delta_range: -0.40〜-0.25` が指すのは **600〜1,000円のプット**である。
両者の積集合は空。

`scripts/daily_check.py:188-202` と `src/backtest/engine.py:140-165` は
この2つをANDで適用しているため、**デルタ情報が付いたオプションは全て除外される**
（現状は JPX 理論価格データにデルタが無く `if opt.delta and ...` で素通りしているため
顕在化していないだけ）。

「20〜40円コア」という戦略名からすると premium_range が意図で、
delta_range が古い想定の残骸に見えるが、どちらを正とするかは戦略判断。

#### (b) `time_based_days` が暦日で実装されている

`config/config.yaml` は `time_based_days: 5  # 5営業日で強制決済` だが、
`src/backtest/engine.py:197` は `entry_date + timedelta(days=5)` と暦日で計算している。
週末を挟むと実質3営業日になる。

（本検証のバックテストでは意図どおり営業日で計算している。）

## 5. 推奨

### 5.1 判断の根拠を整理する

| 論点 | 結論 | 証拠の強さ |
|---|---|---|
| 現行Gate①は直近1年ほぼ発火不能 | Yes | **強**（実VIレンジ18.77〜66.65、実記録17日で0件） |
| 高VIレジームでは年の53%が発火ゼロ | Yes | **強**（シミュレーション137年） |
| 4サブ条件は冗長、SD10は水準条件の重複 | Yes | **強**（条件付き通過率89.6%、SD10がVI水準に比例） |
| 低VIは急落の前触れではない（むしろ逆） | Yes | 中（シミュレーション依存だが単調・N大） |
| 厳しさが損益を改善している | **証拠なし** | 中（4設定すべてで下位。ただし有意差なし） |

**「厳しさに見合うリターンが確認できない一方、機会の約75%と現在のレジーム全体を失っている」**
——これが緩和を支持する根拠。

### 5.2 推奨する変更の方向

単に `vi_threshold: 20 → 25` と書き換えるのは推奨しない。
それでは「日経VIの長期平均が25を超える年」が来たときに同じ問題が再発する。
設計として直すべきは以下の3点。

1. **絶対水準 → 相対水準（VIの1年パーセンタイル順位）**
   VIの長期平均は年によって17〜25と動く。レジームに追随させる。
2. **絶対SD → 変動係数CV（SD10 / MA10）**
   SD10はVI水準に比例するため、絶対値だと水準条件の二重掛けになる。
   CVならVI帯によらず 0.05〜0.08 前後に収まる。
3. **絶対水準は「保険」として残し、OR条件にする**
   相対順位は「万年高VIレジーム」でも発火してしまうため、
   「絶対的に十分安い（VI<=25）」場合も通す OR を残すと頑健。

推奨案（本検証での V8 に相当）:

```yaml
gate_vi:
  mode: "hybrid"                 # absolute | relative | hybrid
  vi_threshold: 25               # 絶対水準（ORの片側）
  vi_10d_avg_threshold: 25
  vi_percentile_window: 252      # 相対水準の参照期間（営業日）
  vi_percentile_threshold: 40    # 1年パーセンタイル順位 <= 40%（ORのもう片側）
  vi_10d_cv_threshold: 0.10      # 変動係数 SD10/MA10（旧 SD10<=1.5 の置き換え）
  vi_10d_slope_threshold: 0.15   # 0.1 → 0.15
```

この設定の期待挙動（シミュレーション）:

| | 静穏 | 平常 | やや高VI | 高VI |
|---|---|---|---|---|
| 年間発火回数 | 9.2 | 10.1 | 8.8 | 5.0 |
| 発火ゼロの年 | 0% | 0% | 0% | **0%** |

**どのレジームでも沈黙しない**のが最大の利点。
より保守的にしたい場合は `vi_percentile_threshold: 30` / `vi_10d_cv_threshold: 0.08`
とすると年間3〜5回程度に絞れる（本検証の V6 相当。delta モードで PF 最良）。

### 5.3 実装時の影響範囲

| ファイル | 変更内容 |
|---|---|
| `config/config.yaml` | `gate_vi` セクションの書き換え |
| `src/indicators/technical.py` | `_add_vi_indicators` に `vi_cv_10` / `vi_pct_1y` を追加、`detect_gate_vi` を mode 対応に |
| `src/signals/gate.py` | `_TECHNICAL_VALUE_COLUMNS` に新指標を追加、通知フォーマットに相対水準を表示 |
| `scripts/build_dashboard.py` | `TABLE_METRICS` とグラフに `vi_cv_10` / `vi_pct_1y` を追加 |
| `tests/` | `detect_gate_vi` の mode 別ユニットテストを追加 |

注意点:

- `vi_pct_1y` の算出には **252営業日分のVI履歴**が必要。
  `MarketDataFetcher` の取得期間が足りているかの確認が必要
  （不足時は絶対条件のみで判定するフォールバックを入れる）。
- `config_hash` が変わるため、ダッシュボード上で閾値変更日として識別される（既存の仕組み）。
- 既存の `history/signals.jsonl` には新指標が無いため、グラフは変更日以降のみ描画される。

`MarketDataFetcher.fetch_market_data_with_vi` に差し替えることで

本レポートの損益に関する数値はシミュレータの仮定に依存している。
